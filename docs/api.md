# Access Hub API

Two endpoints, versioned under `/api/v1`. A project enrolls once per environment,
then pulls the grant list on demand.

---

## `POST /api/v1/enroll`

Exchange a one-time connection code (generated by a hub admin on the project page)
for permanent client credentials.

**Auth:** none — the code is the auth. Rate limited to 10 requests/minute per IP.

**Body** (form or JSON):

| Field | Notes |
|---|---|
| `code` | The `HUB-XXXX-XXXX` code. Single use, expires 15 minutes after issue. |
| `project_key` | The project's slug, e.g. `hrms`. |
| `environment` | `local`, `staging`, or `production`. |

**200 response:**

```json
{
  "client_id": "chub_aau36wpstj0od0j4omyjfdum",
  "client_secret": "Cxd2vkBElehTV7UtHeWQlYNGcoffUXBEQOslOfwETcgSSeKQ"
}
```

The secret is shown **once**. Store both in the project's own database (not `.env`).
Re-enrolling the same environment replaces the secret and clears any prior revocation.

**Errors:** `422` invalid / expired / wrong-project code, `404` unknown or inactive project,
`429` rate limited.

---

## `GET /api/v1/grants`

Return every person that applies to the calling project.

**Auth:** headers

```
X-Client-Id:     chub_...
X-Client-Secret: ...
```

**200 response:**

```json
{
  "generated_at": "2026-09-08T03:32:16+00:00",
  "people": [
    {
      "user_id": 412,
      "name": "Maria Santos",
      "email": "m.santos@example.org",
      "farm": "BFC",
      "department": "Accounting",
      "position": "Senior Accountant",
      "roles": ["division_head", "manager"],
      "active": true
    }
  ]
}
```

`roles` is always an array with **one or more** values from
`manager`, `division_head`, `vp`, `user` (config order). A person can hold several roles
at once; translate each to your local access on your side.

- **Who is included:** the intersection of each person's `scope` and the project's
  `acceptance`. `open` projects get everyone scoped to `all` plus anyone pointed at them
  explicitly; `explicit` projects get only people pointed at them explicitly.
- **Inactive people are included** with `active: false` — so the project can tell
  "removed" from "never here". Delete/disable them locally on your side.
- `farm`, `department`, `position` are display-only and may be `null`. Never make access
  depend on them.
- Every successful call stamps `last_seen_at` on the connection (visible on the hub's
  Connections screen). Routine syncs are not written to the audit log.

**Errors:** `401` missing / bad credentials, `403` connection revoked, `429` rate limited
(60/min).

---

## Revocation

A hub admin can revoke a connection (Connections screen). After that, `/grants` returns
`403` and the project must re-enroll with a fresh code. Revocation has the same lag as
promotion — a project keeps its last grant list until it next syncs.
